## 🔍 핵심 기획 요구사항 및 합의 사항

### 1. 다국어 지원 정책 (영어 전용 MVP)
- `Sentiment.js` 라이브러리의 한글 형태소 분석 제약을 반영하여, **MVP 단계는 영어(English) 입력 전용**으로 스펙을 정의하였습니다.
- 입력 화면에 영어 전용 서비스임을 사용자가 명확히 알 수 있는 가이드라인 UI를 추가합니다.

### 2. 시각적 피드백 제공 (이모지 및 테마 컬러)
- 결과 화면에서 감정 스코어 숫자뿐 아니라 직관적인 감정 인식(Positive: 😊, Neutral: 😐, Negative: 😢) 및 감정 상태에 매핑되는 3가지 다이내믹 테마 컬러 배경을 적용하여 시각적 완성도를 높입니다.

### 3. 추천 답변의 다양성 (Randomized Responses)
- 사용자가 동일한 감정을 분석할 때의 단조로움을 피하기 위해 감정 상태별로 3가지 이상의 공감 메시지를 풀(Pool)로 구성하고, 무작위(Random) 선택 방식으로 제공합니다.

### 4. 입력 길이 유효성 검증
- 최소 2글자 이상, 최대 500글자 이하의 입력 제한을 두어 비정상적인 입력으로 인한 렌더링 에러 및 왜곡된 감정 수치를 차단합니다.

### 5. 최근 3개 분석 히스토리
- 브라우저 로컬 세션 내에 사용자의 최근 3건 분석 히스토리를 유지하여 페이지 전환 없이 이전 결과를 비교 분석할 수 있게 설계했습니다.

## 🛡️ 예외 케이스(Edge Case) 대응 방안
1. **빈 입력값 또는 공백만 입력된 경우**:
   - `alert` 및 인풋 필드 하단 경고 메시지 노출을 통해 분석 요청을 사전에 차단합니다.
2. **2자 미만 / 500자 초과 입력 시**:
   - 분석 버튼을 비활성화하거나 유효성 경고 알림을 표시하여 사용자 입력을 통제합니다.
